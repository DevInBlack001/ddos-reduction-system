# Pinned to exact versions, not >=, on purpose: install.sh and update.sh
# both run `pip install -r requirements.txt` as root, so an unbounded
# minimum lets a future `pip install` silently pull in whatever a
# compromised or malicious release on PyPI happens to publish next,
# installed and imported by a root process the moment it runs. Pinning
# closes that window: an attacker needs to compromise this exact version,
# not any future one satisfying `>=`.
#
# Bump deliberately, after testing, not automatically: `pip install
# --upgrade -r requirements.txt` will not move these versions forward, a
# maintainer has to edit this file. Each version below is the one this
# tree's test suite has actually been run against.
